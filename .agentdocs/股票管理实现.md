# 股票详情实现

## 需求确认

- 股票市场使用 `CN` 和 `US` 两个值：`CN` 对应 A 股与 `CNY`，`US` 对应美股与 `USD`。
- 股票可按批次多次录入，每次保存为 `stockdata` 表中的一条独立记录。
- 每条股票记录入库时生成 64 位随机 ID，并以 16 位十六进制字符串写入 `stock_vid`。
- 用户可选填 `stock_transaction_date`（成交日期）；新增入库时系统自动写入 `stock_entry_time`（录入时间）。
- 股票名称和实时股价通过接口查询，查询失败时前端提示失败，但仍允许保存记录。
- 平均成本未填写时，如果查询到了当前股价，则用当前股价作为该批次平均成本入库；仍查不到时保持为空。
- 当前总价值按 `股票总数量 * 实时股价` 计算；实时价查询失败时前端显示 `--`。
- 行情查询结果写入 `stock_api_cache`，按 `queried_at` 判断 3 小时 TTL；TTL 内同市场同代码直接使用缓存。
- 同一用户、同一市场、同一股票代码已有别名时，录入弹窗查询后自动回填别名；保存时如果用户修改别名，则同步更新该股票所有历史批次的别名。

## 后端实现

新增依赖：

- `yfinance`：查询美股 Yahoo Finance 数据。
- `akshare`：查询 A 股行情数据。

新增模型：

- `autocoin/models/stock_data.py`
  - 表名：`stockdata`
  - 保存用户股票批次数据，包括 `stock_vid`、`user_id`、市场、代码、名称、别名、数量、平均成本、币种、备注、成交日期和录入时间字段。
  - `stock_vid` 是主键，不依赖自增 `id` 列，兼容现有已创建的 `stockdata` 表结构。
- `autocoin/models/stock_api_cache.py`
  - 表名：`stock_api_cache`
  - 保存同市场同代码的股票名称、实时价格、币种和 `queried_at`。
  - 唯一约束：`stock_market + stock_id`。

新增服务：

- `autocoin/services/stock_market_service.py`
  - `StockMarketService.lookup()` 先查缓存，缓存 3 小时内有效。
  - `US` 使用 `yfinance.Ticker` 查询名称和价格。
  - `CN` 优先使用 `akshare.stock_zh_a_spot_em()` 查询 A 股名称和最新价；AKShare 失败时，使用腾讯行情接口兜底。
  - 外部行情库或远端接口异常统一包装为 `StockLookupError`，接口返回可读错误，避免漏成 HTTP 500。
  - `try_lookup()` 用于保存和聚合场景，查询失败返回错误字符串，不中断业务流程。

新增接口：

- `GET /api/v1/stock-management/lookup`
  - 参数：`stock_market`、`stock_id`
  - 返回股票名称、实时价、币种、是否来自缓存、已有别名。
  - 查询失败返回 422，前端提示但允许继续保存。
- `POST /api/v1/stock-management/stocks`
  - 新增股票批次记录。
  - 如果行情查询失败，仍保存记录，并在响应中返回 `lookup_error`。
  - 如果提交了别名，同步更新相同 `user_id + stock_market + stock_id` 的所有批次别名。
  - 如果平均成本为空且行情查询成功，用 `current_price` 自动补齐 `stock_average_price`。
- `GET /api/v1/stock-management/stocks/summary`
  - 按 `user_id + stock_market + stock_id` 聚合。
  - 数量为批次数量求和。
  - 平均成本为 `sum(stock_amount * stock_average_price) / sum(已填写平均成本的 stock_amount)`；未填写平均成本的批次不参与成本分母。
  - 当前总价值为 `sum(stock_amount) * current_price`；查不到价格时为 `null`。
  - 总成本为 `sum(stock_amount * stock_average_price)`。
  - 当前收益率为 `(当前总价值 - 总成本) / 总成本 * 100`，保留 1 位小数；总成本为 0 或当前总价值为空时为 `null`。
  - 当前股价来自行情缓存/接口返回的 `current_price`。
- `GET /api/v1/stock-management/stocks/{stock_market}/{stock_id}/records`
  - 查询某只股票的批次明细。
  - `page_size` 最大限制为 5。

## 前端实现

导航：

- 左侧新增“股票分析”折叠菜单，默认收起。
- “券商收入分析”移动到“股票分析”二级菜单。
- 新增“股票详情”二级菜单，路由仍为 `#/stock-management`。

页面：

- 新增 `frontend/js/stock-management.js`，用户可见页面名称为“股票详情”。
- 页面包含“新增股票记录”区域和“现有资产”区域。
- 点击“新增股票记录”打开弹窗。
- 弹窗字段包含市场、股票代码、股票名称展示、别名、数量、平均成本、成交日期、备注。
- 市场使用单选交互，不使用下拉框。
- 股票代码输入时防抖调用 lookup 接口：
  - 检索中：股票名称展示区显示加载动画和“检索中”。
  - 成功：展示股票名称、回填已有别名，并展示实时价。
  - 失败：展示错误提示，但保留保存能力。
- 股票名称不再使用标题和输入框，仅作为第二行的内联展示信息。
- “股票代码”“股票数量”显示红色必填标记。
- 平均成本输入框提示“请填写本批次平均成本”。
- “现有资产”表格展示聚合结果：
  - 股票代码、股票名称、别名、数量、当前总价值、总成本、当前收益率、当前股价、平均成本。
  - 表头和内容左对齐。
  - 当前收益率正数显示红色，负数显示绿色。
  - 聚合行左侧显示三角箭头，点击聚合行展开批次明细。
  - 批次明细每页最多 5 条，不展示记录 ID。

## 测试覆盖

新增 `TestStockManagement`：

- `test_create_allows_lookup_failure`
  - 验证行情查询失败时仍可保存股票记录。
  - 验证 `stock_vid` 为 16 位字符串，`CN` 写入 `CNY`。
- `test_summary_alias_sync_and_records_pagination`
  - 验证别名修改后同步历史批次。
  - 验证聚合数量、当前总价值、总成本、当前收益率、当前股价、加权平均成本。
  - 验证成交日期保存、录入时间返回、平均成本为空时取当前股价。
  - 验证明细分页最多 5 条。
- `test_lookup_uses_existing_schema_without_id_column`
  - 验证 `stockdata` 不存在自增 `id` 列时，lookup 不会因别名查询返回 500。
- `test_cn_lookup_falls_back_when_akshare_fails`
  - 验证 A 股 AKShare 查询失败时可使用备用行情源。
