# 股票详情实现

## 需求确认

- 股票市场使用 `CN` 和 `US` 两个值：`CN` 对应 A 股与 `CNY`，`US` 对应美股与 `USD`。
- 股票可按批次多次录入，每次保存为 `stockdata` 表中的一条独立记录。
- 每条股票记录入库时生成 64 位随机 ID，并以 16 位十六进制字符串写入 `stock_vid`。
- 用户可选填 `stock_transaction_date`（成交日期）；新增入库时系统自动写入 `stock_entry_time`（录入时间）。
- 股票名称和实时股价通过接口查询，查询失败时前端提示失败，但仍允许保存记录。
- 平均成本未填写时，如果查询到了当前股价，则用当前股价作为该批次平均成本入库；仍查不到时保持为空。
- 当前总价值按 `股票总数量 * 实时股价` 计算；实时价查询失败时前端显示 `--`。
- 行情查询结果写入 `stock_api_cache`，按 `queried_at` 判断 3 小时 TTL；TTL 内同市场同代码直接使用缓存。
- 同一用户、同一市场、同一股票代码已有别名时，录入弹窗查询后自动回填别名；保存时如果用户修改别名，则同步更新该股票所有历史批次的别名。
- 股票页先展示“汇总统计”模块，统计表按币种分行展示，并额外展示统一折算为 CNY 的汇总行。
- “操作”区右侧提供刷新按钮，文案为“刷新数据”，刷新逻辑为刷新本页全部股票数据。
- 统计模块包含资产总价值、持仓总成本、本金收益率、持仓股息率、预计股息/年。
- 统计模块中的资产总价值、持仓总成本、预计股息/年仅在前端展示时保留整数；后端接口仍保留计算精度。
- 缺失行情或股息缓存时沿用股票汇总接口的自动刷新机制；刷新过程中对应统计值显示加载动画，刷新完成后再显示最终计算结果。

## 后端实现

新增依赖：

- `yfinance`：查询美股 Yahoo Finance 数据。
- `akshare`：查询 A 股行情数据。

新增模型：

- `autocoin/models/stock_data.py`
  - 表名：`stockdata`
  - 保存用户股票批次数据，包括 `stock_vid`、`user_id`、市场、代码、名称、别名、数量、平均成本、币种、备注、成交日期和录入时间字段。
  - `stock_vid` 是主键，不依赖自增 `id` 列，兼容现有已创建的 `stockdata` 表结构。
- `autocoin/models/stock_api_cache.py`
  - 表名：`stock_api_cache`
  - 保存同市场同代码的股票名称、实时价格、币种和 `queried_at`。
  - 唯一约束：`stock_market + stock_id`。

新增服务：

- `autocoin/services/stock_market_service.py`
  - `StockMarketService.lookup()` 先查缓存，缓存 3 小时内有效。
  - `US` 使用 `yfinance.Ticker` 查询名称和价格。
  - `CN` 优先使用 `akshare.stock_zh_a_spot_em()` 查询 A 股名称和最新价；AKShare 失败时，使用腾讯行情接口兜底。
  - 外部行情库或远端接口异常统一包装为 `StockLookupError`，接口返回可读错误，避免漏成 HTTP 500。
  - `try_lookup()` 用于保存和聚合场景，查询失败返回错误字符串，不中断业务流程。

新增接口：

- `GET /api/v1/stock-management/lookup`
  - 参数：`stock_market`、`stock_id`
  - 返回股票名称、实时价、币种、是否来自缓存、已有别名。
  - 查询失败返回 422，前端提示但允许继续保存。
- `POST /api/v1/stock-management/stocks`
  - 新增股票批次记录。
  - 如果行情查询失败，仍保存记录，并在响应中返回 `lookup_error`。
  - 如果提交了别名，同步更新相同 `user_id + stock_market + stock_id` 的所有批次别名。
  - 如果平均成本为空且行情查询成功，用 `current_price` 自动补齐 `stock_average_price`。
- `GET /api/v1/stock-management/stocks/summary`
  - 按 `user_id + stock_market + stock_id` 聚合。
  - 数量为批次数量求和。
  - 平均成本为 `sum(stock_amount * stock_average_price) / sum(已填写平均成本的 stock_amount)`；未填写平均成本的批次不参与成本分母。
  - 当前总价值为 `sum(stock_amount) * current_price`；查不到价格时为 `null`。
  - 总成本为 `sum(stock_amount * stock_average_price)`。
  - 当前收益率为 `(当前总价值 - 总成本) / 总成本 * 100`，保留 1 位小数；总成本为 0 或当前总价值为空时为 `null`。
  - 当前股价来自行情缓存/接口返回的 `current_price`。
  - 响应保留原有 `items`，并新增 `portfolio_summary`：
    - `rows`：按原币种分组的统计行。
    - `converted_total`：统一折算为 CNY 的总汇总行。
    - 资产总价值为 `sum(stock_amount * current_price)`；持仓总成本为 `sum(stock_amount * stock_average_price)`。
    - 本金收益率为 `(资产总价值 - 持仓总成本) / 持仓总成本 * 100`，保留 1 位小数。
    - 预计股息/年为 `sum(stock_dividend_per_share_last_year * stock_amount)`。
    - 税后股息为逐条资产税后股息求和：A 股等同于预计股息/年，美股按 `预计股息/年 * 0.8`；CNY 汇总行按各币种税后股息折算后求和。
    - 持仓股息率为 `预计股息/年 / 持仓总成本 * 100`，保留 1 位小数。
    - `asset_value_pending` / `dividend_pending` 标记对应数据仍在刷新中，前端据此展示加载动画。
    - `stock_dividend_per_share_last_year` 来自最近 5 年年度股息汇总：若最新年份派息次数不低于上一年，则取最新年份；若最新年份派息次数少于上一年，认为最新年份尚未派完并取上一年。
  - CNY 汇总使用 `StockMarketService.cny_rate()` 获取汇率；`CNY/CNH` 直接按 1 处理，其他币种通过 Frankfurter 查询，并复用 `stock_query_cache` 缓存 3 小时。
- `GET /api/v1/stock-management/stocks/{stock_market}/{stock_id}/records`
  - 查询某只股票的批次明细。
  - `page_size` 最大限制为 5。
  - 排序优先级为成交日期倒序、录入时间倒序、`stock_vid` 倒序；无成交日期的记录排在有成交日期记录之后。
- `PUT /api/v1/stock-management/stocks/{stock_vid}`
  - 更新当前用户的一条股票批次记录，找不到或不属于当前用户时返回 404。
  - 字段复用新增股票记录请求结构，允许修改所属市场和股票代码。
  - 更新时重新按市场写入币种；平均成本为空且行情查询成功时，仍优先取当前价。
  - 如果提交了别名，同步更新相同 `user_id + stock_market + stock_id` 的所有批次别名。
  - 查询行情失败不阻断保存，响应中返回 `lookup_error`。
- `DELETE /api/v1/stock-management/stocks/{stock_vid}`
  - 删除当前用户的一条股票批次记录，找不到或不属于当前用户时返回 404。

- 平均成本输入框提示“请填写本批次平均成本”。

- 弹窗查询股票信息失败时前端自动重试 2 次；仍失败则在股票名称显示格内展示“查询失败”和“重试”按钮，点击后重新执行同样的重试查询。
- 别名输入框在未被用户手动修改时自动赋默认值：美股使用股票代码，A 股使用接口返回的股票名称；已有或手动输入的别名不会被覆盖。
- “汇总统计”展示组合统计结果：
  - 统计表按币种多行展示，并增加“CNY 汇总”行。
  - “CNY 汇总”行展示在第一行，各币种分组行展示在其后。
  - 没有任何资产数据时仍展示表头，并在表体显示“当前无数据”。
  - 表格使用紧凑展示，减少列间留白。
  - 表格绘制列间竖线，便于区分各列。
  - 统计模块字段为币种、资产总价值、持仓总成本、本金收益率、持仓股息率、预计股息/年、税后股息。
  - 资产总价值、持仓总成本、预计股息/年、税后股息展示为整数金额。
  - 正收益率显示红色，负收益率显示绿色，延续股票页现有涨跌颜色规则。
  - 行情或股息正在后台刷新时，对应统计值显示三点加载动画；后台刷新完成后自动重算并展示。
- “现有资产”表格展示聚合结果：
  - 没有任何资产数据时仍展示表头，并在表体显示“当前无数据”。
  - 表格和展开后的批次明细使用紧凑展示，减少列间留白。
  - 现有资产表格和展开后的批次明细表格绘制列间竖线，便于区分各列。
  - 现有资产聚合行和展开后的批次明细使用深浅间隔行样式，悬停与展开高亮仍优先展示。
  - 展开箭头列和每股派息列额外压缩宽度，减少无效留白。
  - 股票代码、股票名称、别名、数量、当前总价值、总成本、当前收益率、当前股价、平均成本。
  - 每股派息(去年)、股息环比变化、股息率、持仓股息率、预计股息/年、操作。
  - 现有资产表中的预计股息/年按 `数量 * 每股派息(去年)` 在前端展示层计算。
  - 当前总价值、总成本、预计股息/年展示为整数金额。
  - 表头和内容左对齐。
  - 除“操作”列外，每个表头展示排序图标；点击表头可在倒序和正序之间切换。
  - 默认按“当前总价值”倒序排列；空值排序时固定排在最后。
  - 当前收益率正数显示红色，负数显示绿色。
  - 行情或股息刷新中时，现有资产列表内仅显示加载动画，不显示刷新中文字；真实错误信息仍显示文字。
  - 聚合行左侧显示三角箭头，点击聚合行展开批次明细。
  - 批次明细每页最多 5 条，不展示记录 ID。
  - 批次明细按成交日期、录入时间倒序排列，优先成交日期。
  - 批次明细每行提供“编辑”“删除”按钮。
  - 点击“编辑”打开和新增记录一致的弹窗，并预填该批次数据；允许修改市场、股票代码、数量、成本、成交日期、备注和别名。
  - 点击“删除”弹出确认框，文案为“该操作将删除本条股票资产，是否确认？”；确认框随机生成 3 位数字，用户输入正确后才能删除。

## 2026-07-02 接口 Schema 显式化

### 调整目标

- 保持股票管理现有 URL、请求参数、响应字段和前端调用兼容。
- 在路由边界使用 Pydantic 响应模型约束接口结构。
- 为后续接口字段调整、缓存服务拆分和前端拆分提供稳定契约。

### 本次实现逻辑

- 新增 `autocoin/schemas/stock_management.py`。
- 定义股票管理响应模型：
  - `StockItem`：股票批次明细项。
  - `StockMutationResponse`：新增/编辑股票批次响应。
  - `StockMessageResponse`：删除响应。
  - `StockLookupResponse`：股票查询响应。
  - `StockSummaryItem`：股票聚合资产项。
  - `PortfolioSummaryRow` / `PortfolioSummary`：组合统计行与整体统计。
